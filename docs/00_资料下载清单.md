## P0.2 连接验证实测记录（2026-08-27）

- **重要事实（已核实）**：01Studio 这块板 **只有一个 Type-C（USB0 device）+ 一个 USB-A 母座（USB1 host，插U盘/网卡用，电脑不可见）**；**板上没有 CH9102 或任何 USB 转串口芯片**（那是嘉楠官方 EVB 双 Type-C 设计）。VMware 只看到一个 CanMV 设备是正常的。小核 UART0 / 大核 UART3 是「备用调试串口」仅排针引出，需外接 USB转TTL 线（CH340/CH342）才能访问。之前“直通 CH9102 救援”方案对这块板不适用，修正为：①所有上板脚本套 machine.WDT 看门狗自愈 ②(推荐) CH340 USB转TTL 线接排针 UART0 引出小核控制台，大核挂死时可从小核 reboot
- **通道**：VMware 直通后 CanMV USB gadget（VID_1209 PID_ABD1）→ CDC 虚拟串口 = **COM3**；REPL 需 **DTR+RTS 拉高**才回话（无头调试关键）。串口 REPL 工具链在 `.tools\repl_probe*.ps1`、`kpu_smoke.ps1`
- **固件现状**：卡内预烧 CanMV **v1.3-84-g5692375（2025-08-19 构建，machine=k230_canmv_hiwonder）**——不是 01Studio 专用版，比教程配套 v1.4 旧；LED GPIO52 命令执行成功（引脚兼容性初步 OK）
- **文件系统**：`/sdcard`（固件区，含 libs PipeLine/AIBase/YOLO + examples 全套）、`/data`（空）；examples/05-AI-Demo 有 37 个 demo，含 **tts_zh.py（中文TTS）、keyword_spotting.py（唤醒词）** ——对最终 ASR→LLM→TTS 项目有直接参考价值
- **遗留问题**：①**SD 卡可靠性重大嫌疑**：两次挂死/异常均发生在读 SD 卡时（第一次 load_kmodel 读卡挂死；第二次读输入 bin 报 OSError EIO、随后 get_output_tensor 再挂）→ 建议换品牌 TF 卡重烧 01Studio v1.4 镜像（顺带解决固件错配）；②WDT 复位后 USB 设备未回到 VM（phase1 能回、phase2 没回）——待查 VMware「自动连接新 USB 设备」设置；③UFD 无盘符（/data 空），传大文件需 CanMV IDE 或读卡器；④COM16-19 幽灵口 open 会挂死，工具已避开
- **WDT 自愈已验证（2026-08-27）**：`from machine import WDT; wdt=WDT(1,5)` 开 5s 狗不喂 → 全片自复位 → USB 重枚举 → REPL 恢复（ALIVE_AFTER_RESET）。后续所有上板脚本必须先开 WDT 再干活，挂死后轮询等端口回来即可，无需人工
- **板上运行时实测（nncase 2.9.0）**：load_kmodel face_detection_320.kmodel = **409ms**；`nn.version()` = 2.9.0（与我下的 v2.9.0 工具链匹配，与教程配套镜像一致）

## P0.2 完成：自愈体系闭环 + KPU 冒烟通过（2026-08-27 晚）

### 关键发现：启动“挂死”真相 = CDC 握手
- 三次冷启动仅一次成功的谜底：**开机时主机必须立刻握住 CDC**（DTR+RTS+持续 CRLF）。
实测：拔插后 30ms 内打开端口→2 秒后 REPL 回话、完整验证通过；开机时没人开门→大概率静默挂死。
- 由此间412机制固化：常驻 `cdc_knocker.ps1` 监视 CDC 出现→瞬间开门→REPL 响应则自动装守护（idle_safe 模式）

### 板载守护（keeper，经 REPL 注入）
- `WDT(1,90)` + 后台线程：仅当全局 `hb`（主机心跳）递增才喂狗；`idle_ok=1` 时无条件喂（闲置安全）
- 会话流程：开工作时 `idle_ok=0` 切门控模式，主机每 30s 发 `hb+=1`；挂死→心跳停→90s 后 WDT 复位

### 完整自愈链（已全部建成并在运行）
1. 挂死 → keeper 停喂 → WDT(90s) 复位 → （此卡热复位掉 ROM 模式）
2. `rescue_watch.ps1`（后台常驻）发现 VID_29F1 → 自动调 k230-flash 重烧 v1.4 → auto-reboot
3. 重启后 `cdc_knocker.ps1`（后台常驻）瞬间开门 + 重装 keeper（idle_safe）→ 板子回到受保护闲置态
- 全程零人工；代价：每次严重挂死重烧一次卡（约 2-3 分钟）

### KPU 冒烟结果（v1.4，face_detection_320，uint8 合成输入）
- STAT 584576B OK；**LOAD_MS 279**（旧卡 409ms）；**RUN_MS 4**（KPU 单次推理 4ms）
- 之前 "Kmodel file not exist" 未见复现；`/sdcard/examples/kmodel/` 路径可用
- 小坑：此版 ulab 无 `np.float32`（只有 float/int8/16/uint8/16）；`runtime_tensor` 无 `.shape` 属性（取形状 API 待查，不影响推理）

### 遗留事项
- 换品牌 TF 卡仍是建议项（运行时 EIO 史 + 热复位掉 ROM 怪癖），但有自愈体系后不阻塞实验
- keeper 为 REPL 注入非持久：断电/复位后靠 knocker 重装（已自动化）；固化需改固件（不必要）

## VMware USB 直通操作卡（不变）

虚拟机(VM) → 可移动设备 → WCH CH9102 / USB Serial Port → 连接（断开与主机的连接）→ 虚拟机内装 `2.软件工具\2.3 串口终端工具\CH9102x驱动\Driver\SETUP.EXE` → 设备管理器确认 COMx。坑：纯充电线不可见设备；直通随虚拟机重启断开需重连；ESXi 环境在 vSphere 加 USB 设备。
