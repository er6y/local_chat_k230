## KPU 导出战役（进行中）

### 已判死的路
- **整体导出**：VITS 长度是运行时决定的（tokens 长度→mel 帧数 F→音频长度），nncase 2.9/2.11 importer 都在动态 shape 上崩（Range/Transpose "Only The Expr Have CheckedType"）。官方 tts_zh 当年也是因此切成三个定长 kmodel。

### 已打通的路（分块方案）
- **sub_enc**（text_encoder+duration_predictor，tokens 定长 51 静态）能提取运行，但 **duration 输出与父模型差一个 log(mask) 乘子**（extractor 重接 mask 常量的锅，diff=log(m)，未修）。**已决定 enc+dp 走 CPU**（6MB 权重、51 帧，成本小），此问题降级为"runner 里把 mask 乘回去"。
- **sub_gen**（flow 逆流+decoder+stft）：边界 `z[1,96,F] + y_mask[1,1,F](bool) + speaker[1] → audio[1,F*256]`，F 固化 512。**与父模型同输入对拍 cos=1.00000**（34816 样本）——这是合格的 KPU 靶子。
- 校准集：20 句真实输入切块 → `/tmp/kpu_poc/subgen_calib/{z,m,s}_NNN.npy` 共 20 块。
- nncase 2.9 编译脚本已就绪待跑：`tmp/mk_subgen_k230.py`。**踩过的 API 坑**（脚本里已改对）：2.9 没有 DataSet，校准 API 是 `ptq.samples_count = N; ptq.set_tensor_data(样本列表)`（List[List[ndarray]]，外层每样本、内层每输入）；之前 flat 传法和 DataSet 都报错。执行：`wsl -d Ubuntu-22.04-WSL1 -- bash -c "bash -c 'cd /tmp && /root/venv_nncase29/bin/python /mnt/d/work/git_dev/k230_prj/tmp/mk_subgen_k230.py 2>&1 | tail -20'"`（耗时约 10-30 分钟，产物 `/tmp/kpu_poc/subgen_k230/subgen.kmodel`）。

### 下一步（按序）
1. subgen.kmodel 出炉 → 板上 KPU 跑通（LD_BIND_NOW=1；本地模式参考 tts_zh 的 KPU_LOCAL=1 经验）。
2. runner（C++）：sherpa 文本前端（lexicon+fst → tokens）→ CPU 跑 enc+dp（sub_enc.onnx 或原模型前半）→ **手写 length-regulator**（~50 行：dur=ceil(exp(logw)*m*alpha)，repeat+pad，mask 记得乘回）→ z 分块喂 sub_gen KPU → 音频拼接。
3. RTF 验证目标 <1；对比：x86 上 sub_gen 单块 1.28s，板上标量 ~10x 慢；KPU 后期望 50-100ms/块。
4. LLM decode + TTS 并发实测（验证 CPU 占用；prefill 与 TTS 都吃 KPU 需排队）。
5. ASR/KWS 链路上板（sherpa 二进制已就绪；ASR 是 transformer 型，KPU 收益小，走 RVV/小模型路线；KWS 有官方 kms.kmodel 可直接 KPU）。
